# Engine Guide (`crates/*`)

## 1. Scope & Ownership

The Engine area encompasses all high-performance systems and binaries written in Rust located in `crates/`:

- `crates/forge_core`: ECS primitives, math (`Vec2`), transform hierarchies, scene serialization.
- `crates/forge_render`: WGPU graphics pipeline, sprite batching, tilemap rendering, offscreen viewports.
- `crates/forge_physics`: Rapier2D physics simulation, colliders, rigid bodies, raycasts.
- `crates/forge_audio`: Rodio audio graph, bus channels (`master`, `music`, `sfx`), volume control.
- `crates/forge_assets`: Asset database, `.meta` sidecar tracking, UUID indexing.
- `crates/forge_input`: Hardware input polling and logical action mapping.
- `crates/forge_script`: Embedded QuickJS runtime and host engine bindings.
- `crates/forge_bridge`: WebSocket JSON-RPC 2.0 & MCP bridge server for editor/agent control.
- `crates/forge_protocol`: Generated serde message schemas and IPC types.
- `crates/forge_playtest`: Headless playtest harness and assertions.
- `crates/forge_runtime`: Standalone game runtime binary with Win32 windowing.
- `crates/forge_cli`: Command-line developer tool (`forge`).

Tasks working on the engine must restrict their edits to `crates/` and corresponding engine tests.

## 2. Environment & Commands

Always activate the local toolchain before running commands:
```powershell
. .\tools\dev-env.ps1
```

- **Compile check:**
  ```powershell
  cargo check --workspace
  ```
- **Format check:**
  ```powershell
  cargo fmt --check
  ```
- **Format code in-place:**
  ```powershell
  cargo fmt
  ```
- **Clippy (warnings as errors):**
  ```powershell
  cargo clippy --workspace -- -D warnings
  ```
- **Run tests:**
  ```powershell
  cargo nextest run
  ```

---

## 3. Conventions

- **Clean Architecture:** Keep crates decoupled; depend on `forge_core` and `forge_protocol`, avoid circular dependencies.
- **Safety First:** Avoid `unsafe` code unless strictly necessary for OS/FFI bindings (e.g. Win32 HWND or GPU memory allocation) and document safety invariants.
- **Protocol Contract:** When exposing new engine capabilities to Studio or agents, update `packages/protocol/schemas` first and run codegen before updating `forge_bridge`.
- **Determinism:** Headless execution (`--headless`) must be deterministic across platforms.

---

## 4. Do and Do Not

### Do:
- Use `bevy_ecs` patterns for systems and component queries.
- Return structured errors with descriptive messages from bridge commands.
- Support headless mode with frame-limited execution and screenshot capabilities for tests.

### Do Not:
- Do not run heavy test suites locally during routine work; rely on Windows CI.
- Do not edit `crates/forge_protocol/src/generated.rs` manually; it is generated by `pnpm run codegen`.
- Do not introduce blocking I/O calls on the main render/simulation loop.
