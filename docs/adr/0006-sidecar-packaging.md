# ADR 0006: Agent Sidecar Packaging & Distribution

## Status

Accepted

## Context

Forge Studio integrates an autonomous AI agent (`@forge/agent`) to assist creators with real-time scene generation, code editing, diagnostics, and testing. The agent runtime is implemented in TypeScript and executes on Node.js, utilizing Google Gemini models and connecting to the running engine via WebSocket IPC (MCP / JSON-RPC).

In development, the agent sidecar is executed directly by the Tauri host using the workspace-local Node.js binary located at `.tools/node/node.exe` running `packages/agent` entry scripts or module files.

For release packaging (the distributable Windows installer/bundle generated by Tauri), Studio must ship as a self-contained, robust desktop application that works out-of-the-box on creator machines without requiring external Node.js installations or manual environment setup.

This ADR decides and documents the release bundling architecture for the Node.js agent sidecar, while keeping the current implementation scoped to development mode.

---

## Decision

We adopt a **Single-File Bundled JavaScript Executable with Embedded Hermetic Node.js Runtime** strategy for release packaging:

### 1. Production Bundle Compilation (Rollup / esbuild)
- During the Studio release build pipeline (`pnpm build` / Tauri build hook):
  - `@forge/agent` and its production dependencies (including `@forge/protocol`, `@google/genai`, `zod`, and SQLite native bindings) are bundled into a single standalone CommonJS or ESM distribution file:
    `packages/agent/dist/sidecar.cjs`
  - Source maps are stripped or packaged into a dedicated symbols artifact.

### 2. Runtime Sidecar Delivery in Tauri 2
Tauri 2 provides native support for external binaries (`externalBin` / sidecars) and application resource directories (`bundle.resources` in `tauri.conf.json`).

Two valid distribution mechanisms were evaluated:
- **Option A (Chosen): Hermetic Node.js Binary in Tauri Resources:**
  - The minimal portable Windows `node.exe` runtime is packaged under Tauri's `resources/node/` folder along with `sidecar.cjs`.
  - In release mode (`#[cfg(not(debug_assertions))]`), `agent_host` resolves the embedded `node.exe` relative to the current executable path via `tauri::path::PathResolver::resource_dir()`.
  - Command invocation executes: `<resource_dir>/node/node.exe <resource_dir>/agent/sidecar.cjs`.
- **Option B (Alternative Considered): SEA (Single Executable Applications) / Bun Compile / Pkg:**
  - Compiling the entire Node script into a single binary executable using Node's Single Executable Applications (SEA) blob injection.
  - While SEA produces a single binary (`forge-agent-sidecar.exe`), handling native C/C++ addons (e.g. SQLite `better-sqlite3` bindings) requires separate dynamic DLL distribution or custom rebuilds.
  - Therefore, Option A provides superior reliability and debuggability across Windows versions.

### 3. IPC and Protocol Continuity
- The release sidecar uses identical stdio JSON-RPC 2.0 framing (`Content-Length: <len>\r\n\r\n<json>`) as the development sidecar.
- The lifecycle contract (heartbeat ping, crash restart with exponential backoff, credential passing via stdin initialization handshake) is identical in both development and production builds.

---

## Consequences

### Positive
- **Hermetic Zero-Dependency Experience:** Creators do not need Node.js, npm, or any JS toolchain installed on their system.
- **Identical Stdio Protocol:** Dev mode and Release mode use the exact same stdio protocol, test fixtures, and framing routines.
- **Fast Startup:** Pre-bundled JavaScript files execute faster than multi-module resolution across hundreds of `node_modules` files.

### Negative / Trade-offs
- Installer size increases by ~40-60 MB due to the embedded portable Node.js runtime and bundled packages.
- Requires building `packages/agent/dist` prior to Tauri production packaging.
